# Counts-based m Prior Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let `PatientMatching.train/3` take reviewer-confirmed level counts
as a Dirichlet-style prior on m. The prior blends into EM's starting m and is
added to the M-step's expected match counts.

**Architecture:** A single validator in `Trainer` normalizes the three new
options into one prior struct-like map. `initial_m` blends base m with the
prior using pseudo-count k. `estimate_m/4` passes the strength-scaled prior,
restricted to the session's fields, into `em`. That prior is added only where
the field has observations, and never to lambda. `Model` dumps and loads the
new `trained` keys and exposes the comparison signature publicly.

**Tech Stack:** Elixir 1.17+, ExUnit, Jason. Quality gate is `mix check`.

**Spec:** `docs/superpowers/specs/2026-10-20-m-prior-design.md`. Read it
alongside this plan.

## Global Constraints

- New `train/3` options: `:m_prior` (default `%{}`), `:m_prior_strength`
  (number >= 0, default `1.0`), `:m_prior_base_weight` (number > 0, default
  `10.0`).
- With `m_prior: %{}` or `m_prior_strength: 0`, parameters are
  **bit-identical** to training without the options (same inputs, same seed).
- Prior counts never enter `matched` or `total` in `em`.
- The prior is added only for fields in the session's `:fields` **and** with a
  nonzero expected-count sum in that session.
- `ArgumentError` messages are fixed strings and contain no values. Never call
  `String.to_atom` on dump input.
- The dump `version` stays `3`. The comparison signature format is unchanged.
- Package version becomes `0.2.0`.
- All tests use synthetic records only.

## Review Focus

1. Float counts (`%{exact: 2.5}`) are valid and blend like integers. Pinned in Task 1.
2. A prior keyed on a multi-field comparison's name (`:name_order`, `:contact`)
   is valid. An underlying field name (`:zip`) is an unknown field and raises.
   Pinned in Task 1.
3. A non-map `m_prior`, or a field whose value is a keyword list, raises
   `ArgumentError`, not `FunctionClauseError`/`BadMapError`. Pinned in Task 1.
4. `m_init` and `m_prior` on the same field: the base is defaults merged with
   `m_init`, then blended. Pinned in Task 1.
5. An integer strength (`2`) is stored as `2.0` in `trained` and survives a
   dump/load round trip unchanged. Pinned in Tasks 2 and 3.

### Task 1: Prior validation and blended starting m

**Files:**
- Modify: `lib/patient_matching/trainer.ex` (`initial_m/2` → `initial_m/3`, new `prior!/2`, near `validate_initial_m!/2`)
- Test: `test/patient_matching/em_test.exs`

**Interfaces:**
- Produces: `Trainer.prior!(comparisons, opts) :: %{prior: %{atom => %{atom => number}}, totals: %{atom => number}, strength: float, base_weight: float}`
  - Reads `:m_prior`, `:m_prior_strength` and `:m_prior_base_weight` from the keyword `opts`, with the defaults above.
  - `prior`: only *active* fields (raw total × strength > 0), each map filled to all non-null levels with missing levels as `0`.
  - `totals`: raw totals before strength, for every field with a nonzero raw total, even when the strength is 0.
  - Raises `ArgumentError` with three fixed messages:
    - `"m_prior must map comparison fields to non-null level names with nonnegative counts"`
    - `"m_prior_strength must be a nonnegative number"`
    - `"m_prior_base_weight must be a positive number"`
- Produces: `Trainer.initial_m(config, overrides \\ %{}, prior_opts \\ [])`. `prior_opts` takes the same keywords as `train/3`, and the function calls `prior!/2` itself.

test "no prior or zero strength leaves initial m bit-identical" do
  assert Trainer.initial_m(config, %{}, m_prior: %{}) == Trainer.initial_m(config)

test "one label blends 1/11 toward the prior with k = 10" do
  m = Trainer.initial_m(config, %{}, m_prior: %{family_name: %{exact: 1}}).family_name
  assert_in_delta m.exact, (10 * base.exact + 1) / 11, 1.0e-9
  assert_in_delta m.jw_0_85, 10 * base.jw_0_85 / 11, 1.0e-9
  # no level drops to the floor unless its default is already there
  for {l, v} <- m, base[l] > 1.0e-6, do: assert(v > 1.0e-6)
end

test "huge strength makes initial m the prior proportions" do
  m = Trainer.initial_m(config, %{},
        m_prior: %{family_name: %{exact: 3, jw_0_85: 1}}, m_prior_strength: 1.0e9).family_name
  assert_in_delta m.exact, 0.75, 1.0e-5
  assert_in_delta m.jw_0_85, 0.25, 1.0e-5
  assert m.else >= 1.0e-6
end

test "float counts and m_init combine with the prior" do
  init = %{family_name: %{exact: 0.6, jw_0_85: 0.3, else: 0.1}}
  base = Trainer.initial_m(config, init).family_name
  m = Trainer.initial_m(config, init, m_prior: %{family_name: %{exact: 2.5}}, m_prior_base_weight: 2.5).family_name
  assert_in_delta m.exact, (2.5 * base.exact + 2.5) / 5, 1.0e-9
end

test "multi-field comparisons are keyed by comparison name" do
  config = PatientMatching.Presets.patient_mpi()
  assert %{name_order: %{swapped: 2, else: 0}} =
           Trainer.prior!(config.comparisons, m_prior: %{name_order: %{swapped: 2}}).prior
end

test "invalid priors raise fixed messages without values" do
  comparisons = config.comparisons
  for opts <- [
        [m_prior: %{zzz_secret: %{exact: 1}}],
        [m_prior: %{family_name: %{zzz_secret: 1}}],
        [m_prior: %{family_name: %{null: 1}}],
        [m_prior: %{family_name: %{exact: -1}}],
        [m_prior: %{family_name: %{exact: "zzz_secret"}}],
        [m_prior: [family_name: [exact: 1]]],
        [m_prior: %{family_name: [exact: 1]}],
        [m_prior_strength: -1],
        [m_prior_strength: "zzz_secret"],
        [m_prior_base_weight: 0],
        [m_prior_base_weight: -1.0]
      ] do
    error = assert_raise ArgumentError, fn -> Trainer.prior!(comparisons, opts) end
    refute error.message =~ "zzz_secret"
    refute error.message =~ "-1"
  end
  # A preset underlying field that is not a comparison name is unknown.
  preset = PatientMatching.Presets.patient_mpi()
  assert_raise ArgumentError, fn -> Trainer.prior!(preset.comparisons, m_prior: %{zip: %{exact: 1}}) end
end

test "a one-count prior barely moves a converged estimate" do

test "a field with no observations keeps its blended initial m" do

  # repeat with m_prior_strength: 1.0e9 and assert :b ≈ prior proportions (1.0e-5)

test "the prior never enters lambda's numerator or denominator" do
  model = TestModels.fixed()
  config = %{model.config | em_max_iters: 1}
  p = %{{:exact} => 100, {:jw_0_85} => 50, {:else} => 1000}
  plain = Trainer.estimate_m(p, model, config)
  primed = Trainer.estimate_m(p, model, config, m_prior: %{family_name: %{exact: 1.0e6}})
  assert primed.trained.lambda_train == plain.trained.lambda_train
end

test "an unstable field reverts to the blended initial m" do
  # u: exact 0.97, jw_0_85 0.02, else 0.01. Prior proportions exact 0.8, jw 0.15, else 0.05,
  # so even a pinned exact m (0.8) is <= u (0.97).
  # Build m with Trainer.initial_m(config, %{}, m_prior: prior_scaled_to(total)) for total 1 and 10_000.
  r = Trainer.estimate_m(%{{:else} => 1000}, model, model.config, m_prior: prior)
  assert r.trained.unstable
  assert r.parameters == model.parameters
  # total 1: each m is within 1/11 of base. total 10_000: each m is within 2.0e-3 of the prior proportions.
end

test "estimate_m validates its prior" do
  model = TestModels.fixed()

    Trainer.estimate_m(%{{:exact} => 1}, model, model.config, m_prior: %{family_name: %{zzz: 1}})
  end
end
